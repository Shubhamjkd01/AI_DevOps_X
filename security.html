OUR GUARANTEE TO ORGANIZATIONS

🔒 4 Inviolable Security Pillars

ZERO-TRUST COMPLIANT

If an organization or developer gives their repository webhook to AIDEVOPS, they must have 100% assurance that their proprietary codebase, secrets, and customer data can never be compromised, leaked, or stolen. Here is mathematically and architecturally how that is guaranteed:

🔒

1. One-Way Outbound Webhook

ZERO INBOUND CODE ACCESS

• Webhooks do not give repository read permissions: A GitHub Webhook is strictly a one-way notification sent from GitHub's servers to the agent.
• Contains metadata only: The payload only informs that "Workflow #142 failed on branch staging". It contains zero source code files and cannot clone private repositories.
• HMAC SHA-256 Signatures: Every incoming payload is validated using GitHub's X-Hub-Signature-256. Forged or unauthenticated requests are rejected with HTTP 401.

🚫

2. Ephemeral In-Memory Processing

ZERO PERSISTENT CODE STORAGE

• No Code Databases: Your source code is never saved to external hard drives, persistent SQL databases, or central cloud storage.
• Never Used for AI Model Training: Google Gemini processes stack traces strictly in isolated RAM buffers solely to synthesize the AST diff. Your code is never used to train or fine-tune models.
• Garbage Collected Instantly: As soon as the pull request diff is generated, memory pointers are released and cleaned up.

🔑

3. Granular Least-Privilege Scoping

NO ADMIN & NO SECRET ACCESS

• Fine-Grained Personal Access Tokens (PAT): AIDEVOPS only requires 2 minimal permissions:
   • Actions: Read (to read failure logs)
   • Pull Requests: Read & Write (to open automated fix PRs)
• Zero Access to Sensitive Areas: The agent has NO access to organization billing, repository secrets, production deployment environments, or team administration.
• Instant 1-Click Revocation: You can revoke the token at any second directly in GitHub settings.

🛡️

4. AST Syntax Guard & Human Review

NO DIRECT PUSH TO PRODUCTION

• AST Malicious Code Blocker: Every fix proposed by the AI is passed through an Abstract Syntax Tree (AST) validator. Any illegal calls (e.g. os.system, eval(), network exfiltration) are blocked and discarded immediately.
• Zero Direct Pushes to main: The agent is programmatically restricted from ever pushing directly to main or production branches.
• Mandatory Human Approval: The agent only opens an isolated Pull Request (e.g. fix/ci-failure-142). A human engineer must review and merge the code.

❓ Frequently Asked Security Questions

Q: If I give you my repository webhook, can you steal my proprietary code?
A: Absolutely NOT. A GitHub webhook does not give the receiver any access to your repository. It only delivers an outbound HTTP POST alerting that a workflow run has failed. To read the failure log or submit a PR, the agent uses your own token configured in your own environment. No outside entity ever has access.
Q: Does the AI agent ever push code straight to production or master?
A: Never. The agent is hard-coded to only create isolated feature branches (e.g. fix/ci-failure-142) and submit an official GitHub Pull Request with a full diff breakdown. A human engineer on your team must review, test, and approve the PR before it is ever merged.
Q: Where are my API keys and tokens stored?
A: Only on your machine. Your GEMINI_API_KEY and GITHUB_TOKEN stay strictly on your local machine inside your local .env file. They are never transmitted to any external analytics, monitoring, or third-party servers.
